The same code runs inside n8n

        
The workflow file carries this page’s code in its Code nodes. Each customer message takes this path:

        
    
          
  1. WhatsApp events Webhook, POST
    Answers Meta with 200 straight away, so Meta doesn’t retry while the reply is being worked out.
    2. 
          
  2. Verify, parse, dedupe Code
    Checks Meta’s signature on the raw body, drops delivery receipts, and drops a message id it has already answered.
    3. 
          
  3. Answer Code
    Reads the language, intent, service, day and time, then builds the reply from the salon’s data.
    4. 
          
  4. Route Switch
            
    
              
    Salon data or front desk
    Reply is ready; go straight to sending.
    
              
    OpenAI
    Chat completion with the salon’s facts and a JSON reply format; any price in the answer is checked against the price list.
    
            
    5. 
          
  5. Send via WhatsApp HTTP Request
    One POST per message to the Cloud API.
    6. 
        

        
Also in the file: the verification handshake Meta makes when you register the webhook, and a schedule that sends day-before reminders every 15 minutes.

How it was checked

        
n8n itself was not run for this demo. A harness that imitates the n8n parts the file uses (Code nodes, expressions, the Switch, HTTP requests, workflow static data, and Code nodes that can’t read environment variables, as in n8n 2.x) ran the file with WhatsApp and OpenAI mocked. For all 139 test messages it produced the same request bodies as calling the code directly.

        
29 of 29 tests pass; 24 of 24 planted bugs are caught by them.

WhatsApp’s rules, handled in code

      
These are the places a WhatsApp assistant usually breaks after launch. Each is handled in the code and checked by the tests.

      

        

          
The 24-hour window decides how a reminder can be sent

          
A normal message is only allowed within 24 hours of the customer’s last message. After that it has to be a template Meta has approved. So a day-before reminder depends on how far ahead the booking was made:

          

            
Booked this far aheadDay-before reminder

            
              
Less than 24 hoursNone, and the confirmation doesn’t promise one

              
24 to 48 hoursNormal message

              
48 hours or moreApproved template, unless the customer has written since

            

          
Of 168 booking lead times checked hour by hour up to a week, a plain day-before message would land outside the window for 121, if the customer doesn’t write again. The workflow sends those as the template.

        

        

          
Retries, fake posts and receipts get no reply

          
Meta retries notifications, and retries can arrive twice. Anyone who finds the webhook URL can post to it. Every message sent also comes back as sent, delivered and read receipts.

          
In a simulated stream of 120 messages from 40 customers, with 7 injected retries, 10 forged posts and 360 receipts, the workflow sent 120 replies: one per message. A handler without the signature and duplicate checks sent 137.

        

        

          
Every reply fits WhatsApp’s limits

          
Reply buttons: at most 3, titles up to 20 characters. Lists: at most 10 rows, titles up to 24. Text: up to 4,096 characters. Arabic labels count too, so slot buttons read الجمعة 20/11 17:00.

          
139 payloads from the test messages and scripted conversations: 0 over a limit. The longest button title is 18 characters.

        

        

          
One message per reply, because replies now cost money

          
Since 1 October 2026 Meta charges for each service message, the replies sent inside the 24-hour window, after a monthly free allowance. So each answer is built as a single message: a price comes with its booking buttons rather than as two messages.

          
125 of the 125 test messages answered without OpenAI got exactly one message back. 14 of 139 needed OpenAI.

        

      

    

  


  

    

      
What was measured, and what wasn’t

      

        

          
Measured

          
    
            
  • Intent: 106 of 109 on the test set, 28 of 30 on the held-out set. Reply language: 109 of 109 and 30 of 30.
    •

    •

    • 
            
  • The price check passed 10 of 10 written replies with real prices and stopped 10 of 10 with invented ones.
    • 
            
  • 29 of 29 tests pass; 24 of 24 planted bugs are caught by them.
    •

Not measured

    • 
            
  • n8n itself wasn’t run; the harness imitates the parts the workflow uses.
    • 
            
  • The salon, prices, staff and all test messages are invented.
    • 
            
  • Voice notes and photos go to the front desk; nothing is transcribed.
    • 
            
  • Bookings live in n8n’s workflow storage, which suits a demo, not a busy salon.
